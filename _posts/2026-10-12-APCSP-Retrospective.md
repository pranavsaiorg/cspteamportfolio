# APCSP Trimester Retrospective

## Introduction

This trimester in AP Computer Science Principles, I learned how to set up my coding tools, use GitHub, organize work, and plan a real project with my teammates Aadi and Pranav. A major part of our work has been choosing a community project and planning improvements for the Poway Veterans Organization (PVO) website. I have also worked through setup and troubleshooting in VS Code and learned how important it is to keep assignments organized and correctly formatted.

## Setting Up My Tools

One of the first steps was setting up the tools needed for computer science work. I worked with VS Code and the course portfolio workflow, including opening project files, working with notebooks and Markdown, and running or testing work locally. I learned that a project can fail to display correctly when its file structure, front matter, or paths are wrong. Troubleshooting these problems taught me to check the exact file path, required formatting, and error messages instead of assuming the code itself is the only problem.

I also worked on setup tasks and SASS inputs as part of learning the tools and workflow used in class. These early steps helped prepare me to work on larger assignments and collaborate on a shared project.

## Creating a GitHub Account and Learning GitHub

Creating a GitHub account gave me a place to view and organize code, issues, and project work. I learned that GitHub is more than a place to store code. It can also help a team plan features, divide work, record progress, and communicate about problems.

I worked with our team portfolio repository, [pranavsaiorg/cspteamportfolio](https://github.com/pranavsaiorg/cspteamportfolio). I also learned how repositories, issues, commits, and a Kanban board fit into a project workflow. When we needed to make changes, I learned to be careful about which repository I was working in and to understand the difference between viewing a project and having permission to change it.

## Building an About Page and Organizing My Portfolio

I worked on adding an About page and on keeping my portfolio work organized. This helped me understand that a website needs both working features and clear information about the people and work behind it. I also practiced following the course's expected assignment structure, including the correct front matter and file paths. Keeping those details consistent makes it easier for assignments to appear correctly on the portfolio.

## Choosing the Poway Veterans Organization Project

Our team chose the Poway Veterans Organization as our community project. The goal is to improve the website so veterans and other community members can find information and use the site more easily. We discussed features that could make the website more useful, accessible, and organized.

Our ideas include accessibility tools, a Veterans Spotlight, a photo and video gallery, a resource hub, an AI information assistant, and an employment board. These features focus on helping visitors read content, learn about veterans and events, find resources, get answers, and explore job opportunities.

## Creating GitHub Issues for the PVO Project

One of our biggest planning tasks was turning broad ideas into GitHub issues. Our team created 12 issues to describe possible website improvements and break the work into manageable tasks. We also began splitting larger ideas into smaller issues so each task would have a clearer goal and a way to check whether it was complete.

Examples include:

- **Accessibility toolbar:** a main feature for making the site easier to use.
- **Text-size controls:** let visitors increase, decrease, or reset text size.
- **High-contrast mode:** improve readability by changing the display contrast.
- **Read-aloud feature:** let visitors listen to the main page content.
- **Saved accessibility preferences:** remember selected display settings after a refresh.
- **Testing and demonstration:** check the features and prepare evidence that they work.
- **Veterans Spotlight:** highlight veterans and their stories.
- **Photo/video gallery:** show media from past events.
- **Resource Hub:** collect helpful information in one organized place.
- **AI assistant:** help answer common questions about PVO.
- **Employment board:** help veterans discover job opportunities.

We also documented our process for creating issues, including coming up with ideas, breaking large tasks into smaller tasks, organizing work on a Kanban board, and planning testing. This helped us see how project planning connects to the actual development work.

## Learning From VS Code and GitHub Troubleshooting

I learned that small details can cause major problems. Incorrect front matter, a missing or incorrect permalink, a misplaced file, or a wrong path can stop a lesson from showing up as expected. I practiced checking assignment files and making sure each lesson had the appropriate title, category, topic, type, author, and other required fields.

I also learned that collaboration requires understanding permissions. I could not directly approve changes in repositories that were not mine, so I had to find another way to share information, such as copying issue details into the conversation. This helped me better understand the limits of account permissions and the importance of working in the correct repository.

- Work with VS Code, Markdown, notebooks, and project file paths.
- Use GitHub to organize repositories and issues.
- Follow the required portfolio and lesson formatting.

## How Our Team Can Improve Next Trimester

To succeed over the rest of the trimester, Aadi, Pranav, and I should focus on communication, steady progress, and testing.

1. **Set clear weekly goals.** At the start of each week, choose a small number of tasks and agree on what finished work should look like.
2. **Keep GitHub issues updated.** Move tasks on the Kanban board as work starts, continues, and finishes. Add notes when something is blocked.
3. **Divide work clearly.** Make sure every task has a clear owner after our team has discussed and agreed on responsibilities. Avoid duplicate work and make sure no important task is forgotten.
4. **Communicate early.** If someone gets stuck in VS Code, GitHub, or the code, bring it up early so the team can help instead of waiting until the deadline.
5. **Test locally before calling work done.** Run the website in VS Code, test features on desktop and mobile where possible, and check that existing pages still work.
6. **Save evidence.** Use screenshots, test notes, commits, and pull requests to show what changed and prove that each feature meets its goal.
7. **Review each other's work.** Before considering a task complete, have another teammate check the result and give feedback.
8. **Keep the project focused on users.** Prioritize features that make the PVO website easier to use and help veterans and community members find useful information.
